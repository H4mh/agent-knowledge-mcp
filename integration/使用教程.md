# 团队知识库使用教程

> 服务地址：`http://your-akm-server:3000/mcp`
> 适用对象：所有使用 AI agent 编程工具（Claude Code / Cursor / Trae 等）的开发同学
> 维护人：知识库管理员（见文末速查）

---

## 1. 这是什么

团队共享的"踩坑经验库"。你（的 agent）在排查问题时先问它——如果别人踩过同样的坑，直接拿答案，不用从头分析；你解决了别人可能再遇到的问题，随手沉淀进去，下次救的就是别人。

9 个工具（agent 自动调用，你不需要记命令）：

| 工具 | 干什么 |
|---|---|
| `search_knowledge` | 排查前先检索，看是否已有现成经验 |
| `save_knowledge` | 解决问题后沉淀经验（自动查重、敏感信息拦截） |
| `update_knowledge` | 补充/修正已有条目（作者本人可改） |
| `mark_used` | 某条知识真帮到了你，标记一下——被 2 个不同的人用过会自动转"已验证" |
| `get_context` | 开工前拉取某模块的注意事项清单 |
| `save_skill` | 打磨好一个可复用的操作技能后上传共享（SKILL.md 安装入口由系统自动组装） |
| `search_skills` | 接到开发任务先检索团队 skill 库，有无现成技能 |
| `get_skill` | 拉取 skill 的 SKILL.md 与附加文件，按返回的 install 指引写入本地 skills 目录 |
| `update_skill` | 补充/修正已有 skill（作者本人或管理员可改） |

## 2. 接入方式总览

| 客户端 | 接入方式 | 人工步骤 |
|---|---|---|
| Claude Code | **一键全局脚本**（推荐） | 运行 1 条命令 + 重启会话，按 agent 提示回填访问令牌后再重启一次，**所有项目生效** |
| Cursor | 手动配置 | 填一次身份名，注册后回填访问令牌 |
| Trae | 手动配置 | 填一次身份名，注册后回填访问令牌 |
| 其他支持 MCP 的工具 | 手动配置同 Cursor | 填一次身份名，注册后回填访问令牌 |

**身份名规则（所有客户端通用）：**

- 字母/数字开头，只能含字母、数字、`. _ -`，最长 40 字符
- 中文姓名请用拼音（如 `zhangsan`、`wangwu-hd`）
- **先到先得**：请用真实可辨识的名字——知识条目的"作者"、可信度统计都靠它
- 重名了（调用报 401）→ 换一个，如 `zhangsan-p8`、`zhangsan-0421`

**⚠️ 注册后立即把访问令牌写回配置（所有客户端通用）：** 配置里 `Authorization: Bearer` 先填的是**身份名**，它只用来完成首次注册。首次调用成功后，服务端会生成随机访问令牌（`identity_token`）并随该次响应下发——**令牌只显示这一次，注册后立即让 agent 把它写回配置（`Authorization: Bearer <identity_token>`）并重启会话**；丢失只能找管理员 `reset-token` 重发。此后身份名只是署名，不再是凭证。若服务器启用了 `AKM_JOIN_SECRET`，首次注册还需携带 header `"X-Join-Secret": "<团队口令>"`（口令找管理员或团队模板拿）。

## 3. Claude Code 接入（推荐，一次配置全项目生效）

### 3.1 拿到模板

从公司 Git clone 本仓库，或找管理员要 `integration/` 目录（<100KB）。

### 3.2 一键全局接入

任意目录执行一次：

```bash
bash integration/setup-akm-global.sh            # macOS / Linux
```

```powershell
.\setup-akm-global.ps1                          # Windows PowerShell
```

可显式指定身份名（中文姓名请转拼音）：`bash setup-akm-global.sh zhangsan` / `.\setup-akm-global.ps1 zhangsan`。

脚本写入的都是用户级配置（`~/.claude.json`、`~/.claude/settings.json`、`~/.claude/CLAUDE.md`），**本机所有项目共享**，幂等可重复执行。

### 3.3 重启一次会话，完事

重启后打开任何项目，agent 都会自动遵守知识库使用约束。**首次调用完成注册后，agent 会提示你把响应中的 `identity_token` 写回配置并再重启一次——照做即可（令牌只显示一次，写回后丢失才有找回的余地）。** 验证：随便问一句"检索一下知识库"，能返回结果（哪怕提示"未命中"）就是通了。浏览器里也可验证：打开 `http://your-akm-server:3000/`，用访问令牌（identity_token）登录知识门户。

### 项目级接入（可选）

只想在个别项目启用、或不想动全局配置：在项目根目录执行

```bash
bash integration/setup-akm.sh /path/to/你的项目
```

只写项目内文件（`.mcp.json` / 项目 `CLAUDE.md` / 项目 hook），不影响全局。

## 4. Cursor 接入

Cursor 的 MCP 配置 agent 无法自动改写，需人工填一次：

1. Settings → MCP → Add new MCP server
2. Name: `team-knowledge`，Type: `HTTP`
3. URL: `http://your-akm-server:3000/mcp`
4. Headers:

```json
{ "Authorization": "Bearer zhangsan" }
```

先填身份名（如 `zhangsan`）完成首次注册；注册成功后把该次响应中的 `identity_token` 换到 Bearer 后面并重启（**令牌只显示这一次**）。若服务器要求团队口令，再加一个 header `{ "X-Join-Secret": "<团队口令>" }`。

5. **装上工作流纪律**：把 `integration/rules/cursor-rules.mdc` 复制为项目的 `.cursor/rules/team-knowledge.mdc`——这样 agent 才会自觉"排查前先检索、解决后要沉淀"。其他工具的对应样板见 `integration/rules/README.md`

## 5. Trae 接入

在 Trae 的 MCP 设置里手动添加：

```json
{
  "mcpServers": {
    "team-knowledge": {
      "url": "http://your-akm-server:3000/mcp",
      "headers": { "Authorization": "Bearer zhangsan" }
    }
  }
}
```

`Bearer` 后先填身份名（如 `zhangsan`）完成首次注册；注册成功后把该次响应中的 `identity_token` 换到 Bearer 后面并重启（**令牌只显示这一次**）。若服务器要求团队口令，headers 里再加 `"X-Join-Secret": "<团队口令>"`。

- 新版 Trae 支持 Streamable HTTP，直接可用；**老版本只支持 SSE 会连不上**——遇到这种情况联系管理员在服务端开启 SSE 兼容
- 添加成功后看 server 状态是否变绿、能否列出 9 个工具
- **装上工作流纪律**：把 `integration/rules/trae-project-rules.md` 追加到项目的 `.trae/rules/project_rules.md`（没有就整个复制过去）——MCP 只是给了 agent 工具，规则文件才让它知道"排查前先检索、解决后要沉淀"；各工具样板对照表见 `integration/rules/README.md`

## 6. 日常使用（你和 agent 各自要做什么）

### 你要做的

- **开工时**：不用做任何事，agent 会自动 `get_context` / `search_knowledge`（CLAUDE.md 约束 + 会话启动提醒驱动）
- **有感觉时**：agent 说"已入库 #42（draft）"或"发现相似条目"时扫一眼，确认它沉淀的内容对不对
- **别传敏感数据**：密钥、客户数据、身份证号会被服务端硬拦截（报 `SENSITIVE_CONTENT`），内网 IP 等会产生警告但仍会入库
- **打磨了可复用的操作技能**（一套部署步骤、排查流程等）→ 让 agent `save_skill` 上传共享，下次别人直接安装复用

### agent 会自动遵守的（写在 CLAUDE.md 里）

1. 开工先 `get_context` 拉模块注意事项
2. 排查问题先 `search_knowledge`，避免重复踩坑
3. 解决非琐碎问题后 `save_knowledge` 沉淀：写清现象、结论、验证方法
4. 检索未命中且后来自己解决了 → 主动沉淀
5. save 响应里有相似条目且是同一问题 → 改用 `update_knowledge` 补充，不重复新建
6. 某条知识真帮到了 → `mark_used` 标记
7. **接到开发任务先 `search_skills` 查有无现成技能**：命中则 `get_skill` 按 install 指引装到本地 skills 目录再干活，没有才自行解决；打磨好的做法 `save_skill` 上传共享

### 知识条目怎么写才算好

- **title**：一句话说清问题（"Qiankun 子应用切换白屏"）
- **symptom**：现象，别人能拿着它对号入座
- **solution**：结论/办法，直接可执行（"检查 publicPath 是否为 /subapp/<moduleName>/"）
- **domain**：`java` / `frontend` / `mobile` / `infra` / `db` / `workflow`
- **scope**：适用项目——**用 git 仓库名**（`git remote get-url origin` 的末段去掉 `.git`，如 `proj-a`），跨项目通用用 `global`；**未注册的 scope 在首次保存时自动注册，零人工开通**（session-start hook 会在会话启动时直接告诉你本项目的 scope）
- **tags**：技术标签（服务端自动归一化，如 达梦→dameng）

### 条目状态与可信度

- 新条目都是 **draft**；被 **2 个不同的人** `mark_used` 后自动转 **verified**
- verified 条目在检索中排名更靠前；管理员可人工定级或废弃（deprecated）

## 7. 常见问题（FAQ）

| 现象 | 原因与处理 |
|---|---|
| 调用报 401 | 没配 Authorization，或凭证不对：首次注册用**身份名**，注册之后一律用 **identity_token**（名字不再能用）→ 检查 Bearer 后填的是哪个；已注册身份的令牌丢了找管理员 `reset-token` 重发 |
| 401 且 Claude Code 刚接入 | 会话还没重启或身份还没写入，等 agent 走完「身份自配置」流程（含注册后写回 identity_token） |
| 401 且是新身份首次注册 | 服务器启用了团队口令（`AKM_JOIN_SECRET`），请求未携带 `X-Join-Secret` header 或口令不对 → 找管理员/团队模板拿口令，配置里加 header 后重试；口令不对时注册会被直接拒绝 |
| 报 429 | 触发限流（每身份 60 次/分钟；门户匿名浏览按 IP 计），稍等再用 |
| 报 `SENSITIVE_CONTENT` | 内容含密钥/身份证/银行卡等，脱敏后重试（这是硬拦截，不是 bug） |
| 报 `INVALID_SCOPE` | scope 名不合法（字母/数字开头，仅 `. _ -`）；合法的新 scope 会自动注册，被禁用的 scope 找管理员 |
| Trae/Cursor 连不上 | 老版本只支持 SSE → 联系管理员开 SSE 兼容；或升级客户端 |
| Windows 上运行 .ps1 报"禁止运行脚本" | 用 `powershell -ExecutionPolicy Bypass -File .\setup-akm-global.ps1` |
| 检索总是"未命中" | 库里还没人沉淀过——解决了就 `save_knowledge`，做第一个写的人 |
| 想改条目的状态（verified/deprecated） | status 不开放给 MCP，联系管理员 |
| 报 `INVALID_SKILL_NAME` / `INVALID_SKILL_FILE` | skill 名不符合 kebab-case（小写字母/数字/`-`，2-64 字符）或附件超限（≤20 个文件、单文件 64KB、总量 256KB），按报错调整后重试 |
| 报 `SKILL_EXISTS` | 同名 skill 已存在——改用 `update_skill` 补充修正，不要另起名字 |
| 浏览器访问知识门户 | 打开 `http://your-akm-server:3000/`，检索/浏览/Skills 可匿名看；上传编辑与后台需登录（登录令牌 = MCP 配置里 `Bearer` 后那串访问令牌，没注册过身份先让 agent 接入一次注册领取，门户不注册新身份） |

## 8. 管理员速查（服务器 your-akm-server）

```bash
# 连接
ssh -i <密钥> root@your-akm-server

# 用户
docker exec akm-app node dist/scripts/admin.js listusers
docker exec akm-app node dist/scripts/admin.js listusers --legacy   # 列出仍以用户名作令牌的存量账号（迁移用）
docker exec akm-app node dist/scripts/admin.js reset-token <名字>   # 重发随机访问令牌（明文仅此一次显示，线下交付本人写回配置）
docker exec akm-app node dist/scripts/admin.js disable <名字>       # 禁用垃圾身份
docker exec akm-app node dist/scripts/admin.js adduser <名字> --token <token> --role admin

# 知识
docker exec akm-app node dist/scripts/admin.js set-status 42 verified
docker exec akm-app node dist/scripts/admin.js delete-knowledge 42
docker exec akm-app node dist/scripts/admin.js history 42           # 条目修订历史（最近 50 条）
docker exec akm-app node dist/scripts/admin.js export /opt/backup/knowledge-md

# skill
docker exec akm-app node dist/scripts/admin.js set-skill-status <name> verified
docker exec akm-app node dist/scripts/admin.js delete-skill <name>
docker exec akm-app node dist/scripts/admin.js history --skill <name>   # skill 修订历史

# 种子导入（markdown 目录）
docker cp /path/to/seeds akm-app:/tmp/seeds
docker exec akm-app node dist/scripts/import-markdown.js /tmp/seeds

# scope 管理（新 scope 由首次保存自动注册，无需手工建）
docker exec akm-app node dist/scripts/admin.js list-scopes
docker exec akm-app node dist/scripts/admin.js delete-scope <垃圾scope>

# 日志 / 备份 / 升级见 docs/deploy.md
```

> 部署与安全要求（安全组限源、TLS、备份）见 `docs/deploy.md`。
